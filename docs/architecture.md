# 架构

```text
QQ / NapCat → OneBot 11 → 固定版本 AstrBot + 接入插件
                                  ↓ 已认证事件 / 发送回执
                         XZBot Python 核心
                         ├─ 权限、账号与 Profile
                         ├─ 近期上下文、参与投票、工具循环
                         ├─ Markdown 人设与背景检索
                         ├─ SQLite 历史、记忆、订阅、轨迹
                         └─ 云模型、识图、检索、语音
```

主要目录：

| 位置 | 职责 |
|---|---|
| `src/azusa_bot/` | FastAPI、业务服务和存储 |
| `astrbot_plugin_azusa_onebot/` | 普通 QQ 事件桥、发送和回执 |
| `astrbot_plugin_azusa_bridge/` | 保留的官方 QQ 桥接 |
| `ui/index.html` | 本机管理界面 |
| `scripts/` | 初始化、运行、维护和迁移 |
| `tests/` | 合成数据回归测试 |

`core.py` 组织事件处理；`profiles.py` 管理角色隔离；`group_policies.py`、`participation_vote.py` 控制群参与；`memory.py` 保存历史、事实、群记忆及整理进度；`lore.py` 管理背景资料；`trajectories.py` 记录送入模型的上下文来源与结果。

个人记忆采用先限定 scope/subject、再计算词项相关度的检索；背景资料使用分块与全文索引。两者不是同一种检索器，也没有本地嵌入推理模型。真实图片只进入适用的近期事件上下文，旧历史不是默认附图来源。

账号间不共享实时登录，Profile 间不共享角色记忆。owner 根据认证接入提供的稳定 ID 判断，聊天内容、昵称和模型判断不能授予管理权。

AstrBot 原生 PersonaManager/ConversationManager/Provider 不构成本项目当前的角色管线；预设问答、分段发送和工具执行是本项目的实现。独立宿主适配应保持上述业务层不分叉。

## 每轮上下文怎样组装

1. **人物视角**：当前 Profile 名称替换 `${character_name}`，先放完整 Markdown 人设，再放当前场景约定、资料使用方式与表达习惯。切换账号或 Profile 时名字和资料一起隔离，不取聊天昵称作为身份。
2. **说话示范**：启用的 `begin_dialogs` 成对放在人设之后、真实消息之前；只示范台词，不进入真实聊天数据库，也不能作为“刚才发生过”的证据。其开关、内容与使用提示词均可编辑。
3. **记得的事与背景先放**：长期记忆先限定当前账号/Profile/会话及成员，再按词项相关度选最多8条；不会默认拼入这位群友很久之前的原始发言。背景是手动指定的常驻全文、近24小时角色动态片段，以及 SQLite FTS5/BM25 检索的通常最多3个相关片段。启用且满足门槛的话题理解、角色近况也在这一层。
4. **查阅结果仍属背景**：模型可申请查本地资料、有限范围的历史或公开搜索；程序核对权限、额度与来源后，把结果加到背景层再生成。回读历史仅限当前会话、当前成员允许保存的近7天记录，各工具每轮最多一次，总轮数另有限制。查到的旧记录保留时间归属，不能混进近期聊天。
5. **近期真实聊天，再到当前消息**：群聊取本群最近的条数/分钟窗口，另取当前群友与角色已确认送达的近期问答；私聊问答上限12条、30分钟，群内取群级窗口和最多12条问答。发送前按 role、user_id、message_id 去重，优先保留实际群消息的先后次序，再合并已送达问答；并发时若问答配对顺序与群内实际交错顺序冲突，以群内观测为准，以 age_seconds 合并互不重叠的片段。多人聊天以有身份归属的 `recent_conversation` JSON 呈现；`in_direct_dialogue` 标出与当前群友的问答。未发送的候选回复不进入这里。当前消息单独作为最后一条 user 消息，带发送者、编号、文字及自己的图片，不在近期记录中重复。冷场主动发言没有新的触发消息，不伪造一个 current_message。
6. **发送前统一排列与预算**：`request_context.py` 在每次实际模型请求前统一生成上述顺序，包括工具查询后的下一次生成及超限重试。内部检索、裁剪、图片归属仍使用原有结构，预算测量的是最终排列后的文本；另预留回答、示例和图片额度。人设、当前问题和标记常驻的全文不截断，仍放不下就停止该次调用。旧图有原消息标识并放在当前消息前，不能把旧图算到当前没带图的文字上。调用轨迹记录本次排列，新增排列说明也在「提示词」页可编辑。
7. **输出与记录**：内部仍用 `system/user/assistant` 消息角色和 JSON 字段，这是接口协议。`text` 才是角色实际说给群友的话；投票、资料引用、工具状态只在管理轨迹显示，发送回执成功后才成为真实对话。

35段附加提示词在管理页「提示词」编辑；当前替换后的文本和各场景可能使用的段落也可查看。完整人设与预设问答在「完整人设」。规则使用角色名字、群友和第一人称处境来表达，不把聊天写成咨询任务；人物具体性格由每个 Profile 自己的人设和台词示范决定。

此设计参考 [AstrBot 人格与 begin_dialogs 接口](https://docs.astrbot.app/dev/star/guides/ai.html#人格设定管理器) 和本机固定版本 `61335414433db721b3f7ecc93f90deafe0a59d78` 的 `astrbot/core/astr_main_agent.py::_ensure_persona_and_skills`：该实现把人物设定加入 system prompt，并把成对示范放在 contexts 前方。我们保留示范与真实历史的边界；[上游 issue #10369](https://github.com/AstrBotDevs/AstrBot/issues/10369) 也报告过把预设对话误认作真实时间线的问题，它是问题报告，并非已证实的普遍效果或已合并方案。

排列依据：[Anthropic 长上下文建议](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices)建议长资料靠前、问题靠后；[AstrBot 固定版本的普通请求实现](https://github.com/AstrBotDevs/AstrBot/blob/61335414433db721b3f7ecc93f90deafe0a59d78/astrbot/core/provider/sources/openai_source.py#L958)先复制 contexts，再追加当前消息，并把 system 放在开头。这不是所有工具协议的硬性规定：原生工具调用通常继续追加工具结果。XZBot 当前使用自己的有界资料查询循环，因此每轮查询完成后可重新排列为“背景 → 近期聊天 → 当前消息”，没有破坏原生工具消息配对。顺序优化也不等于角色效果或事实准确性的保证。

提示词措辞无法单独保证角色表现。离线回归验证的是名字隔离、实际组装顺序、可编辑性、近期上下文、检索与发送约束；最终语气仍受人设、示例和所选模型影响。
