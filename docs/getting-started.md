# 开始使用

优先使用 [三平台发行包](releases.md) 的 Start-XZBot 入口。下列步骤供源码部署。

## 初始化

在项目目录运行 `sh scripts/setup.sh`：按锁文件建立 Python 环境，仅在文件不存在时复制示例配置和示例人设。它不会开启 QQ，也不会覆盖已有角色、人设、密钥或白名单。`content/` 是本地可编辑数据，示例位于 `examples/`。

运行 `AZUSA_ROOT="$PWD" .venv/bin/python -m azusa_bot.cli serve` 启动回环管理服务。`data/admin.token` 是本地管理口令，在页面中输入；不要发到聊天、提交到 Git 或公开 URL。Mac 的应用入口可通过 `.venv/bin/python scripts/install_desktop.py` 安装；Linux 不运行 Mac 桌面安装脚本。

## 配置顺序

1. 在「模型与语音」填写供应商地址、模型和凭据；兼容接口 key 与目标地址绑定。
2. 在「角色档案」「完整人设」设置角色、别名、语音和示范问答；背景资料和图片素材通过各自页面导入。
3. 完成适用于当前宿主的 QQ 环境安装、登录和账号核对。在「连接与 Owner → QQ 登录」选择已安装的 NapCat 或 SnowLuma 接入路径；保留的官方 QQ 适配器属于另一种身份体系，不能互换 owner 标识。
4. 配置白名单与 owner。先验证本人私聊，再按需启用群聊参与、长期采集和订阅。

QQ 运行环境及进程控制的支持边界见 [平台支持](platform-support.md)。不要在两个运行实例中同时启用同一个 QQ。

## 调用上限与发送结果

「模型与语音 → 调用额度」显示并设置当前 QQ 账号的每日云端请求上限，默认 200 次。该账号的群、私聊和所有 Profile 共用计数，其他账号独立计数。这是本地请求次数限制，不是供应商余额、token 或金额预算。对话、接话与话题判断、记忆整理、云端搜索和语音合成共用；一次回复可能用掉多次，已发出的失败请求也计数。普通收消息及本地检查不消耗此额度。

计数在 UTC 每天 0 点（北京时间 8 点）重置。`cloud_budget` 表示达到这个本地上限；保存更高上限后立即生效，保留已用计数，不会自动重发旧消息。

冷场聊天显示「回执未确认」时，QQ 可能已经收到。程序为避免重复发送不会自动重发。新尝试会在按钮结果与调用轨迹中保留经过过滤的错误码：`send_timeout` 表示等待回执超时，`missing_receipt` 表示缺少有效消息编号，`onebot_retcode_*` 表示接口返回错误码；这些信息本身不能证明账号被风控。旧记录没有具体错误码时，不推测补填。

## 本地数据

默认角色内容在 `content/`，额外 Profile 在 `data/profiles/`；额外 QQ 账号在 `accounts/`。数据库和凭据由应用管理，不通过 Git 同步。更新前备份，恢复时保留原作用域和账号身份。

## 获取订阅内容、编辑对象与查看去向

在「订阅与通知 → 角色动态」保存来源并启用后，点击「一键获取当前内容」，无需等下一次平台更新。它读取接口当前返回的内容，同步所有已启用且绑定该来源的角色；每个来源最多处理 20 条，不补抓全部历史。超过 24 小时的内容只归档到背景资料的「角色动态」文件夹，不当成今天的近况。已处理过的内容不会重复收录，手动删除的资料也不会立刻被重新导入。

「订阅对象」中每个对象都有「立即获取」「编辑对象」「查看记录」。获取默认不生成 QQ 通知；可显式勾选「获取时同时检查新通知」，仅为已启用、仍在白名单中的接收方检查符合时效的新事件，原有去重和回执规则继续生效。手动获取不会调用语言模型，也不会消耗本地云模型请求额度。30 秒内重复点击复用成功快照，平台冷却不能通过点击绕过。

编辑对象可改显示名称或来源 ID，保留当前 QQ 账号内的角色绑定、接收群与图文设置；其他账号复用的对象独立配置。修改 ID 会取消旧来源尚未完成的通知，新来源第一次正常检查仅建立基线。历史资料和投递记录保留原来源。中断的配置写入会在启动时恢复；如显示未完成，使用对象库中的恢复按钮。

「获取与推送记录」按来源筛选，展示手动 / 定时检查的时间、取得的内容与原文链接、收录到哪些角色、哪些群或私聊应接收，以及跳过、冷却或失败原因。QQ 的「等待发送」「已领取」「已确认发送」「回执未确认」分开显示；获取成功不等于 QQ 已送达。记录保留最近 30 天且最多 10,000 次检查。升级前只有原有投递数据，不追补当时没有记录的获取和角色收录过程。
