# XZBot 简明操作手册

## 首次使用

1. 下载对应系统 ZIP，解压到固定目录，运行 `Start-XZBot`。第一次联网安装依赖，完成后打开管理页。具体 QQ 安装和扫码步骤见 [三端部署](releases.md)。
2. 用本机管理口令连接页面，口令保存在 `data/admin.token`，不要发到聊天或公共仓库。
3. 在「连接与权限」登录 QQ、采用正确账号。Owner 填你自己的真实 QQ 账号；配置允许接收消息的群和私聊白名单。Owner 根据 QQ 通道传来的稳定 ID 验证，昵称和聊天中的自称无效。
4. 在模型与语音页面填自己的模型服务、模型名、API key。语音再填 Fish 音色 ID，并在已有使用权限时启用；这些设置只留在本机。
5. 在「角色档案」选择阿梓或灰泽满，或新建自己的 Profile。同一账号当前会话统一使用选中的角色；两个 QQ 同时运行需独立账号工作空间及 QQ 连接。

## 调整角色说话方式

「提示词」可以编辑完整人设、预设问答和全部额外提示词。预设问答用来示范口气；分段回复控制一次回答拆成几条发。将当前整套保存为默认后，“恢复默认”恢复你的版本，“恢复程序初始值”恢复软件自带版本；编辑后要保存。

「背景资料」支持手工输入，无需 URL。按文件夹和添加时间管理，可标记可信类别；重要角色设定可开启全文常驻，其他资料按关键词/检索与按需读取加载。全文常驻会占用上下文额度，不是无限容量。

「对话对象与 QQ 引用理解」和「连续对话判断」控制接话对象的判断。刚聊过只会成为续聊候选；期间其他人插话时仍要判断是否真的在对角色说。QQ 原生回复会单独带上可取得的引用文字及发送时间；不可取得、被撤回或隐私禁止的原文不猜测。历史图片标记不等于已经看见图片。

## 按群控制参与程度

先用页面上方统一的群聊选择框选群，再调整该群的参与、记忆设置。群聊配置预设可以跨角色复用；“应用到当前群并生效”直接启用选中的预设；“载入编辑草稿”只填入编辑区，需要保存才生效。“另存预设”记录一套可复用参数，不等于替所有群启用。

每个角色独立观察群聊，只使用自己实际收到的 QQ 消息和自己已确认发出的消息。聊天判断不再读取其他账号的配置、名字、人设、记忆、判断结果或待发送内容，也不读取跨账号对话对象表。两台设备不需要共享运行状态；即使使用同一台设备，也遵守这个边界。对方未送到本角色的消息不会影响本角色的计划。

在「连接与 Owner」为本角色手动填写已知的其他 Bot QQ 号（配置字段 `onebot_peer_bot_ids`）；这只是身份类型，不会导入对方知识。对方的称呼来自本角色实际观察到的群名片、原生提及或发言，不从管理器读取。未配置的账号按普通群成员处理。

「接话与续聊 → 允许角色间有限互动」默认关闭。开启后，每次实际收到新的有效真人消息，本角色最多回应已配置的其他 Bot **1 次**；使用较短的续聊间隔，但仍须参与计划和发送额度允许。关闭或用完后只观察，普通接话、热烈参与、冷场或切换开关不能绕过上限。一次回复即使分段发送也只计一次；未确认的发送不返还机会，重启不会刷新次数。这是各角色各自的限制，不依赖其他角色报告轮数。

每条合格的群消息先保存本地观察事实：发言人、原生提及、引用及时间。明确单独 @ 自己、在开头叫自己的已配置名字可直接进入回复；引用与提及冲突、无明确对象的“你”、多人交错等先调用 `group_plan`，输出回应、观察或等待，以及所依据的本地消息编号。模型编造账号、引用不可见消息或返回无效计划时保持安静。主动接话的置信度／分项评分在规划阶段检查；正文阶段只围绕已经通过的计划表达。自定义话题理解若启用，可在计划通过后补充话题资料；规划、话题和正文共用本轮模型调用预算。

本地状态可保留多段对话；同一人转向其他成员会改变相应关系，无关群友的插话不会一律撤销已有回答。生成后和每段发送前再次检查计划是否仍有效。真实已发送的消息仍按回执记录；迟到回执不能重开已经结束的对话。`wait` 只是本次不发言，后续实际事件到来再判断，不会自行定时补发。

原生 @ 会携带明确的 QQ 账号，并按本群成员信息补充群名片／昵称；模型分别看到发言人、被引用消息的作者和被提及的成员。同名成员仍按 QQ 号区分，查不到名字时保留账号，不猜身份。回复角色时 @ 普通群友可以是在询问那个人，角色仍可回答；引用角色消息后只 @ 一位群友、不另打文字，也会保留这条提及。已有成员介绍按被提及的 QQ 号读取，并继续遵守本群的记忆授权；手打的 `@数字` 或 CQ 字符串不被当成原生提及。使用此功能需要核心服务和 QQ 桥接都加载新代码。

发送前会拦截与近期可见 Bot 发言或本账号待发送内容文字相同、高度相似的回复，并要求模型有新内容才接话。真人明确要求复述可以例外。它不能保证识别所有语义重复，也不能预知另一账号尚未发送的并发回答。Bot 活动会取消冷场候选；本角色收到相关转向、隐私撤回等变化时，发送前检查会取消过时的回复。群内发言额度和云端预算仍生效。「最近消息处理」中的 `repetitive_reply` 表示重复内容被拦截；`peer_round_limit` 表示本角色的有限互聊机会未启用或已用完。

- 别名、直接 @、QQ 回复、连续追问、热烈参与和冷场发言是不同触发途径。收到消息不一定调用模型，调用成功也不等于已发送。
- 分项投票、置信度门槛、间隔和每日限额决定是否开口。冷场计时和热烈程度进度条显示本地已观察到的状态。
- 「冷场发言 → 立即发起一次聊天」跳过冷场等待；仍受总开关、白名单、QQ 通道及云端请求额度约束。按当前角色设置选择文字或语音。
- 「接话与续聊 → 允许其他群友承接角色刚才的话」默认开启：角色确认送达后 60 秒内、后续不超过 6 条群友消息，另一人说“你”“刚才”“再来一次”等也能进入语义判断，不受普通接话的积攒消息数和判断间隔限制。窗口和条数可改；明确 @ 或回复别人时不接。仍须判断指代、满足评分门槛和续聊短间隔，不是见到“你”就自动回应。只使用本群当前短期公开上下文；其他成员的私聊和个人对话不会被继承。轨迹会显示承接的角色消息 ID、间隔和消息数，判断文本可在「提示词 → 连续对话 → 其他群友承接群聊」编辑。
- 「群语音」按群设置：**自动·不限额（默认）**由角色依人设、对话选择；**关闭**时只用文字或图片；**自动·限额**可填过去 24 小时的合成次数。直接回复、别名、续聊、主动接话及手动／自动冷场发言共用这份额度，用完改发文字，私聊不受影响。额度在同一 QQ 的各角色间共用，重启或改档位不重置。开始合成即计一次，合成失败、发送未确认也计入，避免重复费用；尚未调用合成接口的失败不占额度。页面显示已用、剩余和下一笔释放时间。“不限额”只取消群级限制，全局语音授权、长度和云端请求额度仍生效。
- 要朗读指定内容，先选目标群，再到「群聊参与 → 群语音 → 自定义文字发语音」输入原文并发送。当前角色的 Fish 音色直接合成输入内容，群里收到一条 QQ 语音。发送需要 Bot 在线、目标群在白名单内，以及「模型与语音」启用云端 API、配置 Fish Audio 密钥并授权当前音色。手动合成共用该群的语音额度和每日云端调用额度。合成失败时页面会提示原因；如果 QQ 回执未确认，请先到群里核对，再决定是否重新发送。
- 模型页面的每日云端额度是本机请求次数上限，不是供应商余额。`cloud_budget` 达到上限时在这里调整；提高额度不会重发之前的消息。

## 记忆、轨迹与订阅

单条消息想让 Bot 忽略，可以在正文开头加 `（（`，例如 `（（这句只和群友聊`；英文 `((` 也支持，前面可留空格或换行。不需要闭合括号。此条文字及附件不会触发回复、模型调用、群聊上下文、历史、记忆或调用轨迹；带这个前缀的被引用消息也不会作为上下文回读。下一条没有前缀的消息照常处理，不会改变成员记忆开关。群聊、私聊和管理页对话测试均适用，`/帮助`、`/隐私` 可查看说明。

这是 XZBot 的逐条忽略规则，不会撤回 QQ 消息或对其他群友隐藏。别人去掉前缀后手动转述的文字无法自动识别；也不会自动删除启用本功能以前已保存的资料，需要时在「记忆与历史」删除。

「记忆与历史」按当前群/私聊浏览每个成员的历史、已整理记忆、整理时间，支持纠错和删除。观察历史与形成长期记忆不同：有聊天记录不代表已经提炼出稳定事实。群友隐私开关和删除仍有效。

「记忆与历史 → 成员档案」先选择顶部的会话和成员，再查看两层固定背景：成员介绍，以及近 72 小时的互动摘要。保存介绍后会标为“手动固定”，自动整理不覆盖；自动介绍会随有依据的新信息更新。摘要显示实际发言时间、整理时间和来源历史编号，可直接纠正，也可在「记忆与历史」记录列表删除。关闭自动记录会清除自动介绍和摘要，手动明确保存的介绍保留；「忘记我」或清除成员会一起删除。

后台在原有记忆整理调用中同时生成这些内容，不在每次回复前额外调用模型。只有确认送达的角色回复才可用于互动摘要；未发送的候选回答不会变成共同经历。新安装或旧版本升级后不会凭空出现档案：可等待后续发言触发整理，或到「成员权限」选中成员，勾选“包含已经整理过的原文”再点“整理已保存的历史”。云端整理仍遵守调用额度，按实际输出计费；单次摘要预留最多 3200 输出 token，避免新增字段被截断。

自动整理由后台约每分钟检查一次，不再阻塞收消息和发送回复。累计达到本群的整理条数，或最早未整理发言超过最长等待时间，即可排到后台处理；默认 12 条或 30 分钟，在「记忆与历史 → 本群设置」可改。即使之后没人说话也会检查。每轮最多整理一位符合条件的成员，按等待顺序轮转，受云端额度、失败退避和服务运行状态限制；没有新原文就不反复付费改写。成员档案页显示当前待整理条数、上次尝试、上次完成和结果，手动固定介绍保持不变。

组装回复时默认带当前成员的介绍与最近最多 3 条互动摘要；明确引用或 `@` 另一位群友时，可带入同群且允许记录的那位成员的介绍和最近 1 条摘要。其他群、私聊和其他角色的资料不参与。固定内容先于最近对话和本条消息，整组成员记忆最多 3600 字、12 条；额外检索内容优先裁减。72 小时按来源发言时间计算，旧历史重新整理不会刷新事件日期；较早摘要仍可按需检索。调用轨迹标明固定介绍、近期互动、额外召回，以及档案版本、互动时间和来源编号。新增的“成员背景与近期互动整理”“成员档案与近期互动的使用”提示词在角色的额外提示词中可查看和编辑。

「调用轨迹」显示触发消息末尾、候选回答、分项分数/置信度、资料与记忆引用和发送结果。候选回答可能因判断不合适、权限变化或限额而未发送；回执未确认也不能证明 QQ 没收到，系统不会自动重发以免刷屏。

群里只发 QQ 原生 `@角色`、不附加文字，也会进入直接回复，由角色自然应声；不需要开启自主接话。白名单、Bot 电源、回复间隔和调用额度仍然有效。轨迹标为“原生 @唤醒”，正文保持为空，不替群友编造问题，也不把这次招呼写成长期记忆事实；短期上下文保留原生 @ 标记，方便后续接着聊。`@其他人`、`@全体` 和手打的 CQ 文本不会被当成对角色的原生点名。可在角色的额外提示词中编辑“只有 @ 没有正文时的回应”。

在「调用轨迹 → 按消息」可按会话和成员筛选处理记录。每条显示实际触发处理的消息编号、发送者、接收时间，以及已有轨迹中的可用文字节选。展开后按顺序列出每次参与规划、话题判断、回复生成、重试、联网搜索与语音合成，并说明调用用途、模型和结果。引用与近期发言另列在各次调用的输入消息中。这里读取本地记录，不消耗模型额度。消息处理记录保留编号和结果，不额外保存正文。`（（` 消息完全不留记录。较旧的调用轨迹被清理后，处理记录可能找不到关联调用。

新接收记录会标记原生 `@`、QQ 引用、直接消息或普通群聊；旧记录显示「旧版未记录」，不会猜测。若显示 `cloud_backoff`，意味着这条消息已收到，但在调用前被服务退避拦截；可查看触发退避的前次故障代码、当时剩余等待秒数。退避不会事后补发这些消息。模型输出 JSON 或接话规划字段不合要求，只让本次处理失败，不再触发整个角色所有会话的服务退避；网络、服务限流等真实服务故障仍保留退避。

普通自主接话通过投票后，其他群友在生成期间继续聊天不会单独导致取消；原提问者又发了更新消息、原消息离开当前上下文、候选超过 45 秒或权限已变化时仍会取消。热烈参与保留更短的 15 秒有效期。发送前中止会显示“没有向 QQ 发出发送请求”；已经请求 QQ 却没有可靠回执则显示具体安全错误码，两者不会再混作同一种结果。

同一群的待判断消息进入有界队列，不同成员按入队顺序处理；同一成员尚未处理的普通连续发言会合并到最新一条，原文仍按既有采集规则保留，明确的 `@`、引用和指令不这样合并。每群最多等待 16 条，账号合计最多 128 个处理中或排队任务，最长等待 60 秒。出队时重新读取群上下文、权限和续聊状态；若前一条回答正在发送，会最多等 5 秒回执，再以已确认的内容组装上下文。队列满、合并、超时或配置变化均显示处理原因。排队只是保留判断机会，仍遵守接话投票、冷却和额度，不保证每条消息都调用模型或发言。

队列只在内存保留短期任务，重启不会重放旧消息。隐私退出立即生效，不会排在聊天任务之后；以 `（（` 开头的消息仍完全跳过。队列中的群之间不共用群锁，但仍共享账号的模型并发上限。在「调用轨迹 → 按消息」可查看当前等待数量；有实际等待的调用也会显示排队时间。

使用 QQ 的引用功能回复角色旧回答时，新版会在确认发送后建立“回答消息编号 → 原问题”的关联，最多沿明确引用回溯 3 层，带上原发言者和时间。另一个群友引用也能找到起因，不会把原提问者当成当前发言者。详情中的「引用回答的原始问题」可查看溯源结果，相关提示词也可在额外提示词中编辑。长期关联需要原问题已允许保存到历史；未保存的只能使用仍在内存的短期对话。删除、过期、关闭该成员记录后不再读取。旧版回答仅在完整文本、发送时间和成功记录唯一吻合时回溯，找不到或有歧义就留空，不自动翻遍群历史，也不重新加载旧图。

「订阅与通知 → 订阅对象」统一管理 B 站直播、动态、视频投稿，微博和 Steam 来源。消息订阅可选多个群/私聊；角色动态可复用来源，让近一天公开事件成为角色近况。对象可修改，手动“立即获取”无需等轮询。先配置来源再按需填写平台要求的凭据，不需要无差别填满所有凭据框。

角色动态的「一键获取当前内容」和预览显示近一天匹配的内容；切片标题带投稿时间，不声称已经看过整个视频。获取与推送记录说明来源、同步的角色、接收群/私聊、成功/跳过/失败原因。

直播状态检查成功且在五分钟内时，当前状态优先于旧聊天和历史开关播记录。如果候选回答明确说出相反的当下状态（如来源为“直播中”，回答却说“刚下播”），会先拦截，在现有调用额度允许时最多重新生成一次；仍矛盾就不发送。正常回答不会因此增加调用。调用轨迹会显示来源状态、候选状态和拦截结果，原错误候选不会被标为已送达。这是针对明确直播状态表述的检查，不是全文事实核验；状态过期、查询失败或多个直播来源不明确时不会强行推断。规则提示词可在角色的额外提示词中编辑：「当前近况与旧聊天的优先关系」「近况冲突后的重新措辞」。

“未直播”不能证明“刚下播”。角色动态单独保留成功轮询观察到的状态变化区间：上一次仍在直播到第一次未直播之间，而不是把最近刷新时间当成下播时间。同一状态的后续检查和短时间重启不会重置这个区间；成功观察相隔超过五分钟时，按有缺口重新建立基线，不猜中间发生了什么。首次检查即未直播时，没有可靠下播区间。旧资料和旧台词中的“刚刚”也不会作为当前时间依据。

在「订阅与通知 → 角色动态」可设置“刚开播／刚下播”的时间范围，默认 15 分钟，可填 1–60 分钟。这是角色措辞的范围，不是平台保证：只有整个变化区间都在范围内才支持“刚刚”。时间已久、区间跨过门槛或没有观察到变化时，明确的“刚开播／刚下播”候选会走同一个最多一次重写流程，轨迹显示具体原因和时间区间。新提示词「近况时间与“刚刚”的依据」可在本页或额外提示词中编辑。近一天动态依旧进入背景，但其发布时间不证明角色此刻仍在做那件事；切片投稿时间也不代表片中事件发生时间。

## 运行、备份和升级

关闭网页不会停止 Bot。管理页顶部电源按钮暂停/启动服务；托管 QQ 运行时可关闭 QQ 虚拟机释放内存，Windows/Linux 外部 NapCat 由其自身管理。显示器熄屏不等于睡眠，电脑必须保持运行及联网才能持续在线。

「更新与备份」先做本机备份。版本更新默认显示“官方更新源”，后台仍通过 GitHub 获取发行版；选择“自定义更新源”才显示地址输入框。支持每 6 小时检查和自动下载，安装需点击“安装并重启”。安装会短暂停核心和桥接，保留密钥、私人资料、历史与 QQ 运行时。RC3 及更早版本需要手动升级一次才能使用更新器；源码目录使用 Git 更新，不接受自动覆盖。

首次异常先看 QQ 连接状态、发送回执及模型诊断；本地测试成功只证明模型链路，不代表 QQ 在线。不要反复点发送或反复扫码替代定位。操作手册之外的安装、来源同步、手工构建见 [源码与构建说明](source-build.md)。
