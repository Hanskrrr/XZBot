# 凭据、私有数据与代码仓库

Git 只同步可发布的源码、测试、示例和通用文档。仓库可见性不能代替密钥管理。

- Mac 默认使用项目范围的钥匙串。迁移到 POSIX 服务器可显式使用 0700 目录、0600 文件的凭据后端；该文件未加密，绝不能提交。
- API 接口写入凭据，返回配置状态；不回显完整 key。兼容接口凭据保留地址绑定。
- `data/`、`accounts/`、`content/`、本地配置、环境变量文件、数据库、日志、截图、私有 ZIP、旧 Git bundle 都不进入仓库。
- 人设、聊天、记忆、订阅对象可能含个人信息，不能当作公开示例提交。
- 例外仅为本次明确选择发布、经筛选的两个基础角色模板，位于 `src/azusa_bot/starter_profiles/`。其结构只允许角色资料、音色 ID、公共来源和提示词；不复制部署目录或数据库，不含 Owner、群目标、成员记忆、Cookie、令牌与 API key。
- 私有迁移包含明文凭据和个人资料，只通过受控私有渠道转移，不上传为仓库文件、Release 或 CI artifact。

本地 hooks 和 CI 执行 `scripts/check_repository.py`，检查候选文件路径及高置信度密钥模式。检查不会打印命中的密钥值，也不能替代人工审查；钩子本身可被绕过，CI 是否阻止合并还取决于远程分支保护。

若凭据已经被上传，先撤销/轮换它，再清理 Git 历史和已有副本。仅删除最新文件或添加 `.gitignore` 不会清除旧提交。

## 私有开发与公开下载分开

可以将开发仓库设为 private，另建只用于下载的 public 仓库（例如 `XZBot-downloads`），由私有仓库的 CI 将检查后的 ZIP、SHA256、验证报告和版本说明发布到下载仓库。GitHub 的 Release 访问权限跟随所属仓库，不能让私人仓库中的某一个 Release 单独公开；公开下载仓库不需要复制私人开发历史。跨仓库发布需要仅授权到下载仓库的 GitHub App 或精细权限 token，存入 Actions Secrets。

当前发行包包含可执行的 Python 源码。分开仓库能隔离开发历史、配置和私人资料，不能让下载者看不到包里的程序代码；若希望连程序源码也不公开，需要另行设计编译发行与许可证策略。公开基础角色同样可以被下载者读取。
